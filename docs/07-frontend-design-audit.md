# 前端设计审查

## Design Read

AIxxts 是团队内部 AI 行业情报工作台，核心用户是日常快速阅读的只读成员和做维护配置的管理员。设计语言应是克制、中性、信息优先的内部产品界面，接近轻量 admin console 和知识流阅读器，而不是营销官网、AI 展示页或复杂数据大屏。

本审查采用 `docs/05-product-design.md` 作为产品目标，以 `design-taste-frontend` 的反模板化原则作为负面清单。该技能本身不适合直接指导后台表格和多步骤管理界面，所以本次只抽取其中适用于本项目的约束：无 AI 紫色渐变、无营销 hero、无装饰性大图、无模板化三卡片、无 em dash 字符、统一 tokens、明确状态、稳定响应式和可访问性底线。

## 设计参数

### 产品参数

- 产品类型：内部行业情报工作台
- 优先端：桌面优先，移动端保持可读
- 首页目标：第一屏直接看到今日精选，不做营销 hero
- 内容密度：中等偏高，支撑每天 10-20 条精选扫读
- 后台目标：只覆盖 MVP 维护，不做复杂运营系统

### 前端栈参数

- 框架：Next.js App Router + TypeScript
- 样式：Tailwind CSS v4 + CSS semantic tokens
- 图标：Phosphor Icons，当前符合单一图标族原则
- 字体：系统中文 sans 栈，适合内部工作台
- 主题：当前为浅色主题
- 主要半径：`--radius: 8px`，符合卡片半径不超过 8px 的产品约束

### 设计 dial

- `DESIGN_VARIANCE: 3`
  - 内部工作台需要稳定、可预测的信息架构，不需要强视觉实验。
- `MOTION_INTENSITY: 2`
  - 保留 hover、focus、active 反馈即可，不做滚动叙事和装饰动画。
- `VISUAL_DENSITY: 6`
  - 首页列表应能扫读 10-20 条，后台表格应中等密度。

### Token 建议

- 背景：使用近中性色，不要让整个界面都落在绿色系。
- 前景：统一使用 `--foreground`，避免局部 `bg-black` 或纯黑。
- 强调色：保留单一 teal accent，所有链接、focus、主操作和选中态应共享该语义。
- 状态色：success、warning、danger 已定义，应只用于真实语义状态。
- 边框：`--line` 可继续承担分隔，不要再叠加大量装饰线。
- 半径：卡片、按钮、输入框可以统一 8px；若后续按钮改 pill，需要先写明规则。

## 当前正向判断

- 当前没有 AI 紫色、蓝紫 glow、霓虹渐变和大面积营销视觉。
- 当前使用 Phosphor Icons，未混用多套图标库。
- `globals.css` 已有 semantic tokens，后续可以低成本统一视觉。
- 顶部导航高度约 64px，符合内部工作台的桌面导航高度。
- `focus-ring` 已有基础键盘焦点样式。
- 卡片半径使用 `rounded-md` 和 8px token，符合产品文档要求。

## 页面逐项检查

### 全局壳层

当前状态：

- `AppShell` 已提供 sticky header、桌面导航、移动横向导航、开放预览标识和 GitHub 链接。
- 视觉上偏轻量工作台，没有营销化组件。

风险：

- 桌面导航和移动导航都缺少明确 `aria-label`。
- 当前路由未体现 active nav state，也没有 `aria-current="page"`。
- GitHub 图标链接只有 `title`，后续应补充稳定的可访问名称。
- 页面缺少 skip link，键盘用户每次进入页面都要先经过导航。
- Header 背景和全局背景都偏绿，长期看可能导致状态色和品牌色边界不清。

建议：

- 桌面 nav 使用 `aria-label="主导航"`，移动 nav 使用 `aria-label="移动主导航"`。
- 当前路由链接增加 active 视觉态和 `aria-current`。
- 图标-only 链接补 `aria-label`，图标本身保持 decorative。
- 在 body 顶部增加跳到主内容的 skip link。
- 保留 teal accent，但把背景和分隔 token 调回更中性的 gray 或 zinc 方向。

### `/` 今日精选页

当前状态：

- 页面结构符合「首页直接出现今日精选」目标。
- 已替换 placeholder，包含顶部状态区、关键指标、10 条 mock 精选、生成中状态和空状态。
- 主内容宽度已对齐到 1120px 左右，符合产品设计目标。

风险：

- 真实数据接入后需要继续验证长英文标题、超长来源名和多行 AI 解读。
- 当前页面是静态 mock 数据，加载、错误和权限状态仍需在接 API 后补完整交互。

建议：

- 保持当前排名列、主体列和右侧信号/操作列规则，不要在接入真实数据时退回纯单列卡片。
- 移动端排名和元信息进入同一 metadata 行，标题和解读保持优先阅读。
- 原文链接使用明确文本或图标加可访问名称，避免只有 icon。
- 未生成状态应保留最近一次成功生成日期和下一次计划生成时间。

### `/digests` 历史回看页

目标状态：

- 日期回看不应做成营销式卡片墙，应是可快速定位日期的历史列表。
- 桌面端可以左侧日期列表加右侧摘要，或顶部日期筛选加列表。

检查清单：

- [ ] 默认按最近日期倒序。
- [ ] 每天显示生成状态、精选数量、候选数量和生成时间。
- [ ] 日期选择在 1024px 以上不挤占今日列表阅读宽度。
- [ ] 空历史状态说明还没有生成记录，不展示空白页。
- [ ] 失败日期展示错误摘要入口，不能只用红色标记。
- [ ] 移动端日期选择不产生横向溢出。

### `/items/[id]` 内容详情页

目标状态：

- 详情页是证据页，重点是原始摘要、来源、采集时间、互动数据、所属 digest、入选原因和 LLM 输出信号。

检查清单：

- [ ] 顶部保留返回今日精选或历史日期的路径。
- [ ] 原文标题和来源链接明显，但不做大 hero。
- [ ] 原始摘要、AI 解读、入选原因分区清楚。
- [ ] 多源重复报道以紧凑列表呈现，不做重复卡片堆叠。
- [ ] 互动数据和采集时间对齐，数字使用稳定宽度。
- [ ] LLM 输出需要标注基于输入材料，避免看起来像未核验事实。

### `/admin` 管理后台

目标状态：

- 管理后台采用表格、表单、开关和状态徽标，不使用装饰性大图。
- 后台不需要营销图形、三列功能卡、玻璃拟态或大标题 hero。

表格检查清单：

- [ ] 表头固定语义清楚，列名短而具体。
- [ ] 行高建议 44-52px，支撑中等密度。
- [ ] 时间、数量、状态、操作列稳定对齐。
- [ ] 表格工具栏只放搜索、筛选、主操作和必要批量操作。
- [ ] 状态徽标同时使用文本和颜色，不依赖颜色 alone。
- [ ] 错误摘要可展开查看，不把长错误直接塞进表格行。
- [ ] 空数据、加载、错误、无权限状态都有独立设计。

表单检查清单：

- [ ] Label 在输入框上方。
- [ ] Placeholder 不充当 label。
- [ ] Helper text 和 error text 位于输入框下方。
- [ ] 必填、禁用、只读、保存中、保存失败都有状态。
- [ ] 开关用于启用和停用，选择项使用 select 或 segmented control。
- [ ] 提交按钮位置固定且文案一致，例如「保存来源」而不是多套同义 CTA。
- [ ] destructive 操作需要确认，不只靠红色按钮。

8. 禁用模板化和营销化组件
   - 原因：产品明确是内部工作台。
   - 禁止：AI 紫色渐变、营销 hero、三列功能卡、装饰性大图、scroll cue、装饰性状态点、版本号 hero、em dash 字符。

## 响应式要求

- 桌面 1440px：首屏应看到 header、页面标题、今日元信息和至少第一条精选。
- 桌面 1024px：导航必须单行，列表右侧元信息不能挤压标题。
- 平板 768px：列表列布局开始收敛，操作入口仍可触达。
- 手机 390px：移动导航可横向滚动但不能造成页面整体横向溢出。
- 手机 360px：长英文标题、长 URL 来源名、两句 AI 解读不能重叠。
- 所有固定格式元素需要稳定尺寸，hover、focus、加载文本不能改变整体布局。

## 状态设计要求

首页状态：

- 今日未生成
- 今日生成中
- 今日生成成功
- 今日生成失败
- 今日已过期或不是今天
- 候选池为空
- 精选为空

历史页状态：

- 无历史记录
- 日期加载中
- 日期生成失败
- 搜索无结果
- 历史项缺少原文链接

详情页状态：

- 内容不存在
- 原文链接失效
- 多源合并为空
- LLM 输出缺失
- 采集 payload 可折叠查看

管理页状态：

- 表格加载
- 表格为空
- 保存中
- 保存成功
- 保存失败
- 删除确认
- 无权限
- 会话过期

## 可访问性检查

- 页面语言已为 `zh-CN`，保留。
- 所有 nav 需要 `aria-label`。
- 当前页面需要唯一且可定位的 `main`，skip link 应指向它。
- icon-only 链接和按钮需要 `aria-label`。
- 表单必须使用真实 label，不用 placeholder 代替。
- 错误信息使用文本说明，必要时配合 `aria-invalid` 和 `aria-describedby`。
- 状态更新使用 `aria-live="polite"`，例如生成中、生成失败、保存成功。
- 颜色对比按 WCAG AA：正文 4.5:1，大字和 UI 图形 3:1。
- focus visible 已有基础，但后续所有自定义按钮、tabs、开关、表单控件都要继承。
- 不依赖颜色 alone 表达启用、失败、成功。
- 支持 200% zoom 下不重叠。
