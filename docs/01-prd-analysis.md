# PRD 分析

## 产品定位

本项目不是通用资讯站，也不是深度行业研究平台。它的核心价值是把团队每天需要分散浏览的 AI / 大模型行业新闻、官方更新、开发者社区内容和平台热点内容，压缩成一份可回看的「每日精选」。

第一阶段应优先保证采集、去重、排序、生成、发布这条链路稳定，而不是追求覆盖所有平台。

## MVP 必做

1. 候选池持续采集。
   - RSS / 官方博客 / Changelog。
   - Hacker News、Reddit 等可公开检索或 RSS 化来源。
   - YouTube 先用 AI 频道 RSS feed 接入真实视频，后续有 key 时再启用 Data API 全站关键词搜索。

2. 每日精选生成。
   - 每天固定时间取过去 24 小时内容。
   - LLM 综合影响力与社区热度排序。
   - 输出 Top 10-20。
   - 每条附 1-2 句基于原内容的解读。

3. Web 呈现。
   - 首页直接展示当天每日精选。
   - 支持按日期回看。
   - 当前开发版本取消登录拦截，开放预览。

4. 管理能力。
   - 管理员维护数据源、关键词、生成时间、LLM 模型配置。
   - 角色和只读权限作为后续可恢复能力保留。

## MVP 暂不做

- 深度研判 / 竞品分析报告。
- 面向客户开放。
- 分钟级推送。
- Twitter/X、抖音、小红书的自动化采集默认实现。
- 复杂企业 SSO。

## 平台接入判断

### YouTube

可进入 MVP。无 key 阶段先用 YouTube 频道 RSS feed 采集可信 AI 频道池；这能接入真实视频，但不等同于全站热点搜索。官方 Data API 支持关键词搜索，当前官方文档显示 `search.list` 属于独立 Search Queries 配额桶，默认每天 100 次搜索调用。后续配置 key 后，MVP 需要控制关键词数、分页数和刷新频率，避免无意义消耗配额。

### Twitter/X

不进入 MVP。官方 API 支持 recent search，但按资源读取计费，当前公开文档显示 Posts Read 为 $0.005 / resource。是否接入取决于团队明确预算上限，以及是否愿意承担平台规则频繁变化的维护成本。

### 抖音

PRD 草稿中「无直接开发者 API」需要修正。抖音开放平台能看到关键词视频搜索 / 视频垂搜相关能力，但它不是零门槛全站热点 API，存在权限申请、关键词管理、时间窗口和合规限制。建议 Phase 3 先做专项可行性验证，不放入 MVP。

### 小红书

不进入 MVP。公开开放平台能力更偏账号、营销和已知对象查询，是否能稳定、合规地按 AI 关键词监测全站热点需要单独商务/接口确认。

## 核心风险

- 数据源权限和计费会变化，平台接入必须做成可插拔。
- 候选池去重不能只按 URL，同一事件会被多源报道。
- LLM 解读必须受原文约束，不能产生额外判断。
- 定时任务不能依赖用户访问网页触发。
- SQLite 足够支撑 MVP，但数据访问层要避免和 SQLite 强绑定，便于后续迁移 PostgreSQL。

## 建议确认项

仍建议在开发前由产品侧确认：

- 每日生成时间，默认建议 08:00。
- 是否需要生成后主动提醒，默认建议企业微信机器人。
- Phase 2 Twitter/X 月预算上限。
- 抖音/小红书是接受人工整理，还是先询价新榜、千瓜等商业数据服务。
- 初始团队人数和管理员名单。
